Context retrieves a specific memory; several portable rates turn the task into selection

The Lyft episode is usually represented as a personality trait—but a rideshare question activates its exact $30/hour rate. More broadly, once the bank contains several memories that can serve as exchange rates, the model usually chooses one.

Not always—but dominant once there are several.

With one portable rate present, it is selected in 46% of calls. With two to four, a portable rate is selected in 73–76%, and some displayed rate is copied in 81–89%.

Portable rates are defined from Stage 1: memories repeatedly copied across questions when shown alone—C 37/50 · D 27/50 · F 18/50 · H 39/50. The declined shift G is excluded because it is usually interpreted backwards rather than as a portable rate.

Specificity: a close contextual cue can retrieve a memory that otherwise enters reasoning only as a trait. Default operation: when several usable numerical memories are available, the model usually solves the problem by selecting one exchange rate rather than integrating the evidence.
Reading limits. “Selected” means the final implied $/hour matches exactly one displayed memory within ±3%. This is behavioral matching, not proof that the trace is causally faithful. The Lyft heatmap uses 36 calls per question; C, D, F, and H use 52, 30, 34, and 48 respectively. The portable-rate classification is empirical and post hoc, so the next experiment should preregister the class and repeat targeted question–memory contrasts.
